# ADR-001. Варианты системы мониторинга ферм

### Автор
Дикунов М.А.

### Дата
24.09.2026

## Контекст

Компании «АгроТех Х» нужен MVP для мониторинга животных, управления кормлением и водоснабжением на нескольких фермах. На каждой ферме разрешены один сервер и необходимое количество edge-устройств. Из-за нестабильной связи основные функции должны работать без интернета.

В компании уже есть ERP 1С:Агро, шина сообщений и системы аналитики. Их используем для складского учёта и отчётности. Видеоаналитика работает локально на готовой модели партнёров.

| № | Участники | Сценарий | Описание |
|---|---|---|---|

| 2 | Видеоаналитика, ветеринар | Оценка состояния | 1. Выявить признаки болезни или гибели. 2. Передать наблюдение ветеринару для проверки. |
| 3 | Оператор, оборудование | Кормление и вода | 1. Задать расписание. 2. Управлять кормушками и поилками. 3. Контролировать фильтры и сообщать о неисправностях. |
| 4 | Оператор, система | Учёт и прогноз | 1. Пересчитать поголовье. 2. Получить остатки и расход корма. 3. Рассчитать прогноз потребления. |
| 5 | Администратор, камеры | Подключение оборудования | 1. Зарегистрировать камеру или устройство. 2. Выбрать адаптер производителя. 3. Проверить работу. |
| 6 | Агент фермы, центр | Работа без интернета | 1. Продолжить местную работу. 2. Сохранить события. 3. Синхронизировать после восстановления связи. |
| 7 | Аналитик, внешние системы | Метрики и API | 1. Получить базовые показатели. 2. Добавить собственную метрику. 3. Передать данные через API для веб-/мобильного приложения или другой системы. |

## Нефункциональные требования

| Требование | Значение |
|---|---|
| Доступность | 99,95% |
| Оповещение | Не более 5 секунд от возникновения нештатной ситуации |
| Видеоаналитика | Обработка в реальном времени |
| Синхронизация | До 10 минут при работающей связи |
| Масштабирование | «Центральный сервер — агенты», без фиксированного ограничения числа агентов, ресурсы увеличиваются с нагрузкой |
| Расширяемость | Добавление сервисов, адаптеров и метрик без изменения существующей логики |
| Автономность | Местная работа и уведомления без интернета |

## Основное решение — обработка на edge

[Контекстная диаграмма](C1-main.puml)

Видеоаналитика и сервис инцидентов размещаются на edge-устройствах рядом с камерами. При обнаружении опасности устройство включает местную сигнализацию, не обращаясь к серверу фермы или в головной офис.

Сервер фермы предоставляет местный интерфейс, управляет кормлением, ведёт учёт и синхронизирует данные с центром. Центральная система объединяет данные ферм и передаёт их в ERP и аналитику компании.

**Преимущества:** отказ сервера фермы не останавливает edge-оповещения, новые камеры можно подключать с добавлением edge-устройств.

**Недостатки:** больше оборудования и сложнее его обновлять и обслуживать.

## Альтернатива — обработка на сервере фермы

[Контекстная диаграмма](C1-alternative.puml)

Видеоаналитика и сервис инцидентов работают на единственном сервере фермы. Edge-шлюзы подключают датчики и исполнительные устройства. Остальные функции и взаимодействие с центром остаются такими же.

**Преимущества:** проще установка и сопровождение, можно совместно использовать вычислительные ресурсы сервера.

**Недостатки:** отказ сервера останавливает видеоаналитику всей фермы, расширение ограничено его мощностью.

## Ограничения и риски

- Нужны камеры с ночной съёмкой и размещение с минимальным количеством слепых зон. Ошибки модели проверяет оператор.
- Камеры подключаются по проводной сети, wi-fi канал используется как резерв связи с центром при наличии покрытия.
- Для основного варианта нужны резервные edge-устройства в критических зонах и бесперебойное питание.
- Один сервер остаётся точкой отказа части функций.
