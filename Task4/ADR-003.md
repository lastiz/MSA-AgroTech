# ADR-003. Выбор решения

### Автор
Дикунов М.А.

### Дата
24.09.2026

## Контекст

Сравниваем два варианта платформы мониторинга ферм:
- **Основной:** видеоаналитика и оповещение на edge-устройствах.
- **Альтернативный:** видеоаналитика и оповещение на сервере фермы.

Требования приведены в [ADR-001](../Task1/ADR-001.md), сервисы и интеграции — в [ADR-002](../Task2/ADR-002.md).

## Критерии сравнения

| Критерий | Основной вариант | Альтернативный вариант |
|---|---|---|
| Автономность | Местные функции работают без интернета | Аналогично, пока доступен сервер фермы |
| Время оповещения | Короткий путь на edge, без обращения к серверу | Локальная обработка, но все камеры используют ресурсы одного сервера |
| Отказоустойчивость | Отказ сервера не отключает edge-оповещения; нужен резерв критических зон | Отказ сервера останавливает всю видеоаналитику фермы |
| Масштабирование | Можно добавлять edge-устройства для новых камер | Ограничено мощностью сервера |
| Расширяемость | Новые сервисы, адаптеры и метрики через общие контракты | Аналогичные возможности, так как границы сервисов сохранены |
| Сопровождение | Больше устройств, сложнее обновления и диагностика | Меньше вычислительных узлов, проще обслуживание |
| Стоимость MVP | Дополнительные расходы на edge и резервирование | Может быть дешевле при небольшом количестве камер, но нужен мощный сервер |
| Синхронизация | События проходят через сервер фермы в центр | Меньше промежуточных передач; тот же механизм хранения и повторов |

## Решение

Рекомендую **основной вариант с распределённой edge-обработкой**. Для этой задачи важнее сохранить обнаружение опасности и местное оповещение при отказе сервера фермы. Кроме того, новые камеры можно подключать, добавляя edge-устройства, а не постоянно увеличивая мощность одного сервера.

Главный компромисс — более высокая стоимость оборудования и сложность поддержки. Альтернативный вариант удобнее для небольшого пилота, если приоритетом являются простота и бюджет, но его зависимость от единственного сервера существенна.

Таким образом, основной вариант предпочтительнее по устойчивости аварийного мониторинга и масштабированию, альтернативный — по простоте эксплуатации.
